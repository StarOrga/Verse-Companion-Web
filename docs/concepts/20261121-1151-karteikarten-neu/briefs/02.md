## What each design must show (screens)

Same screen set in all three designs so they compare fairly (use `data-screen` per state; click-through wiring between
them):

1. **Start / deck briefing** — "Deutsch: N Entscheidungen · ≈ M min · betrifft X Texte", the game frame (score,
   streak, daily goal, rank — reimagined), the entry to the foreign-language veto list ("Italienisch, Japanisch,
   Russisch, Portugiesisch: KI hat 199 entschieden, 9 unsicher").
2. **A convention question** (cross-language): „Großbuchstaben oder normale Schreibweise, wo das Englische normal
   schreibt?" — options with real examples: Schließen / SCHLIESSEN (11 Texte), Passagierquartiere /
   PASSAGIER-QUARTIERE, pt Médio / MÉDIA, Trancado / BLOQUEADO; "gilt für alle Sprachen" visible.
3. **A term question**: „Wie soll „Open“ überall heißen?" — Öffnen (5× gesammelt) vs Offen (2×), betrifft 10 Texte,
   plus "Beides falsch, selbst schreiben" and "Nicht meine Entscheidung"; hotkey hints on desktop, swipe affordance
   on phone.
4. **Answer feedback** — the moment after a tap: reward (points, combo/streak, impact "23 Texte vereinheitlicht"),
   the Rückgängig affordance, auto-advance.
5. **Deck finished** — "Alles geklärt für Deutsch", what changes and when (next learn run), the reimagined
   leaderboard/progress, per-language "% geklärt".
6. **Veto list** for foreign languages — rows: term, chosen text, German back-translation, reason, unsure ones on
   top with a warning mark (`--sc-warning`), one "Sieht falsch aus" per row.

Real data to use (live table 2026-11-21): open cards de 54, it 67, pt-BR 52, ja 45, ru 35 (253). German deck after
filters ≈ 20 decisions, first deck ≤ 10. Example veto rows: it Main Thruster → „Propulsore principale" (zurück:

it Offline → „disconnesso" (zurück: „Getrennt", Mehrheit 6 : 1); ru Offline → „НЕ В СЕТИ" (14 : 2). Other German
term cards: Comm → Nachricht 10× / COMM 2×; None → „-" 8× / Keine 1×; Power → LEISTUNG 5× / Energie 1×. The only
answered card so far: Weapons → Waffen (6×) vs Waffenauswahl (1×). Leaderboard sample: use neutral placeholder
names ("Du", "Admin 2", "Collaborator") — no real personal data.

## Direction ideas for the three designs (each must be a genuinely different game metaphor)

Suggested — the author may sharpen them, but keep them orthogonal:

- **d1 · Missions-Briefing (Star-Citizen-Cockpit)**: the deck is a mission with a contract board; each decision is an
  objective; reward = UEC-style credits + reputation tier; streak as "Dienstzeit"; leaderboard as crew roster.
- **d2 · Kartenspiel / Swipe-Deck**: physical card stack in the centre, cards fly left/right on answer (Tinder-like
  on phone, arrow keys on desktop), combo multiplier, daily goal as a ring around the deck, leaderboard as a small
  podium.
- **d3 · Holo-Quiz / Arcade-Run**: a run of N rounds with a timer-free progress track, level-up moments, XP bar,
  achievements/badges for conventions ("Schreibweisen-Meister"), leaderboard as a high-score table.

All three stay inside the app's look (dark, cyan accent `--sc-accent`; elevated-access colours: this tab is
admin-only — the admin red `--sc-accent-hot` stays on admin nav marks only, never inside the game view; worse values
use `--sc-warning`, never `--sc-danger`). Phone: one column, swipe, bottom dock clear of the feedback launcher
(`--sc-float-bottom`), `dvh` for tall surfaces. Motion is allowed but drawn as states (screens), not required to
animate.

## Carry over / constraints

- Round 1's decisions are settled — no analysis view re-asking them. A design round may carry auto-notes
  (annotations) on open detail points, e.g. which swipe direction means what, whether the leaderboard shows other
  admins by name.
- Page-level project rules: no native `title` tooltips in the mock (use visible hints / kbd), one primary action per
  screen, navigations as anchors.
- Round CSS classes need the `mock-` prefix or per-design scoping (`[data-design="dN"]`) — the gate refuses bare
  classes in a live round.
- Not part of this page: the user's plugin feedback about the concept tool itself (Live-Treue hover hints, green dot
  on the note FAB) — the session handles that separately.
