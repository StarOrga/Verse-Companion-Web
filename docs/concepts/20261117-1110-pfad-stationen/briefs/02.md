## Facts for the findings (verified; cite them, do not invent others)

- Today's words: "Nachschub" appears in **69 lines** of `public/i18n/de.json` (67× the bare word, 7× in compounds such as
  "Nachschub-Slots"). The code type is `Nachschub` (`src/app/hq/nachschub/nachschub.model.ts`); a line is a `SupplyItem`
  with `packageId`; an Einsatz links to a package by `packageId`.
- "Einsatzgruppe" is already a visible word of the app for a private **friends group** (`public/i18n/de.json`: "Lege eine
  Org oder Einsatzgruppe an, um Freunde zu ordnen."). It is also historically loaded in German (the SS units of that
  name). Both lenses rule it out.
- Limits: 7 active slots (`NACHSCHUB_MAX_SLOTS = 7`), name ≤ 28 characters, Einsatz name ≤ 40, wish quantity ≤ 999.
- Quantity contract today: taking a wishlist position into a Nachschub **moves** the quantity off the wishlist
  (`NachschubService.createFromWishlist` / `addFromWishlist`); "Nachschub leeren" returns open lines to the wishlist.
  A wish has **no** reference to a package; the only link is the line's `className`.
- Assigning from outside the HQ is technically possible today without a schema change: `NachschubService` is a root
  service, `addFromWishlist(packageId, [{key, qty}])` adds to an existing one, `createFromWishlist({picks, name?})`
  creates one; the item must already be a wish. No caller outside the HQ exists yet. The existing route from the cart is
  a link (`hqNachschubPickLink` → `/hq?pick=…#planen`).
- A reusable picker exists for the Bestand: `src/app/hq/nachschub/nachschub-target-picker.ts` ("an existing active
  Nachschub or a new one", performs the write itself).
- A group also holds things that are no wishes (a sale with an aUEC goal, gather lines, events), so the rule can only be
  "a group is a goal with Einsätze; wishes can be assigned to it", never "a group is a list of wishes".
- Name generation: the edge function `nachschub-names` proposes a name; a user-given name wins.

## The two lenses (agents) — their verdicts

- Product lens (devops:pox): ship the model "a wish is assigned to a group and stays a wish"; name **Projekt / Project**
  (rank 1), then Vorhaben, Operation (collides with org "Ops" and is nearly a synonym of "Einsatz"), Kampagne,
  Unternehmung; "Einsatzgruppe" a clear no; Auftrag/Contract is the game's own term. Assign with a small picker (up to 7
  active groups + "new", whole wished quantity preselected, stepper for a part, undo in the toast); from the Codex only
  assigning — no planning, renaming, emptying, archiving, no sale. Rows: a marker only. Risks: the quantity contract
  flips (high), a rename storm over ~100 texts (medium: rename visible texts only, keep code identifiers and analytics
  event names `nachschub`), double truth wish ↔ group (medium: removing a wish that is assigned asks first).
- Design lens (devops:designer): name **Operation**; four glyphs (below), pick "Route"; assignment inside the wish station.

## The view's content — write exactly these topics and decisions (German, plain language, no jargon, no em-dash runs)

Briefing (`section[data-analysis-briefing]`):
- `data-briefing-what`: Geprüft wurde, wie der Pfad zeigt, dass ein Wunsch schon verfolgt wird, und was „Nachschub“ dabei
  heißen soll. Ergebnis beider Prüfungen: Ein Wunsch wird einer Gruppe von Einsätzen zugeordnet und bleibt ein Wunsch.
- `data-briefing-why`: Heute verschwindet ein Wunsch aus der Liste, sobald er im Nachschub liegt, und im Codex sieht man
  davon nichts.
- `data-briefing-potential` (kpi): value "69", unit "Textzeilen", label "tragen heute das Wort Nachschub".
- Three topic chips with `data-share`: t-name 30, t-regel 40, t-codex 30. `data-briefing-duration`: "≈ 5 min".
- L1 block: short = the kpi; long = a `flow` display "Wunsch → Zuordnung → Einsätze → Besitz" plus 2–3 sentences.

Topic `t-name` — "Name und Symbol":
1. `d-name`, mode `wording`, label "Name der Gruppe", question "Wie soll die Gruppe von Einsätzen heißen?".
   Suggestions (id → text): `projekt` → "Projekt" (rec, why: sofort verständlich, passt zu Bergbau, Handel und Verkauf,
   keine Kollision mit Spielbegriffen), `operation` → "Operation" (Spielerjargon, aber Orgs planen ihre „Ops“, und es ist
   fast ein anderes Wort für Einsatz), `vorhaben` → "Vorhaben" (weich und deutsch, kein gutes englisches Gegenstück),
   `kampagne` → "Kampagne" (klingt nach Story-Event), plus `custom`. Situation: „Einsatzgruppe“ scheidet aus (belastetes
   Wort, und die App nennt so schon Freundesgruppen). Stakes: Rund 69 sichtbare Textzeilen und das HQ-Menü.
   Example (`data-example`): a small before/after of one real sentence, e.g. "Nachschub „Flotte ausbauen“ · 2 von 5
   Einsätzen" → "Projekt „Flotte ausbauen“ · 2 von 5 Einsätzen".
2. `d-icon`, mode `picture`, label "Symbol der Gruppe", question "Welches Symbol steht für die Gruppe?". Four options, each
   with `[data-opt-media]` holding an inline SVG (viewBox 0 0 24 24, `fill="none" stroke="currentColor" stroke-width="1.8"
   stroke-linecap="round" stroke-linejoin="round"`, rendered large enough to judge):
   - `route` (rec) "Route": paths `M5 17v-4a3 3 0 0 1 3-3h8a3 3 0 0 0 3-3`, `M5 17a2 2 0 1 0 0 4a2 2 0 1 0 0-4z`,
     `M19 3a2 2 0 1 0 0 4a2 2 0 1 0 0-4z`. Consequence: Ein Weg mit Start und Ziel, dieselbe Bildsprache wie die Route im HQ.
   - `knoten` "Verbundene Punkte": `M12 3a2 2 0 1 0 0 4a2 2 0 1 0 0-4z`, `M5 16a2 2 0 1 0 0 4a2 2 0 1 0 0-4z`,
     `M19 16a2 2 0 1 0 0 4a2 2 0 1 0 0-4z`, `M10.9 6.9L6.1 16.1`, `M13.1 6.9L17.9 16.1`, `M7 18h10`. Consequence: Mehreres
     gehört zusammen, liest sich aber leicht als „Teilen“.
   - `fahne` "Fahne am Weg": `M6 21V3`, `M6 4.5h12l-3 3.5 3 3.5H6`, `M3 21h6M13 21h2M18 21h3`. Consequence: Ein Ziel, aber
     nur eines, und es erinnert an „melden“.
   - `stufen` "Stufen zum Ziel": `M3 20h5v-5h5v-5h5V7`, `M18 3a2 2 0 1 0 0 4a2 2 0 1 0 0-4z`. Consequence: Schritt für
     Schritt, liest sich aber als Rang oder Level.
   Situation: Das heutige Symbol, ein Fach mit Pfeil, sagt „Lieferung“. Gemeint ist ein Weg aus mehreren Einsätzen.
   The mocks of this round already use "Route" as a stand-in; say so in `data-context`.
3. `d-wort`, mode `yesnoalt`, label "Wort Nachschub", question "Soll das Wort „Nachschub“ ganz verschwinden?", rec `yes`
   (why: Was ankommt, heißt schon Inventar, Hangar oder Sammlung; ein viertes Wort für denselben Zustand verwirrt).
   yes: Alle sichtbaren Texte tragen den neuen Namen; im Code und in der Messung bleibt der alte Bezeichner.
   no: „Nachschub“ bleibt als Wort für das, was aus der Gruppe ankommt. alt: free text.
   Stakes: Zwei Begriffe im HQ oder einer.

Topic `t-regel` — "Was Zuordnen bedeutet":
4. `d-menge`, mode `single`, label "Wunsch bleibt Wunsch", question "Was passiert mit einem Wunsch, wenn er zugeordnet wird?".
   Options: `bleibt` (rec) "Er bleibt ein Wunsch und ist markiert" — consequence: Die Liste zeigt ihn weiter, „Leeren“
   löst nur die Zuordnung. `wandert` "Die Menge wandert wie heute in die Gruppe" — consequence: Der Wunsch verschwindet
   aus der Liste, bis die Gruppe geleert wird. Situation: Heute verschiebt das Nehmen die Menge von der Wunschliste weg;
   ein Wunsch kennt seine Gruppe nicht. Stakes: Zähler, „Leeren“ und Rückgängig hängen daran. Finding display: a `compare`
   or `flow` showing "heute: Wunsch 3 → 0, Gruppe 3" vs "neu: Wunsch 3 · 3 zugeordnet". rec-why: Sonst „verschwindet“
   der Wunsch genau dann, wenn man anfängt, ihn zu verfolgen.
5. `d-zaehler`, mode `yesnoalt`, label "Zähler im Kopf", question "Zählt die Zahl am Wünsche-Symbol zugeordnete Wünsche mit?",
   rec `yes` (why: Ein zugeordneter Wunsch ist noch nicht erfüllt). no: Die Zahl zeigt nur, was noch keiner Gruppe gehört.
6. `d-entfernen`, mode `single`, label "Zugeordneten Wunsch entfernen", question "Was passiert, wenn du einen zugeordneten
   Wunsch entfernst?". Options: `fragen` (rec) "Nachfragen, ob auch die Zuordnung gelöst wird" — consequence: Ein Dialog
   mehr, aber keine stille Lücke in der Gruppe. `still` "Die Zuordnung wird still mitgelöst" — consequence: Schnell, aber
   der Einsatzplan der Gruppe verliert sein Ziel ohne Hinweis. `sperren` "Entfernen geht erst nach dem Lösen" —
   consequence: Sicher, aber zwei Schritte. Situation: Künftig hängen Wunsch und Gruppe zusammen; heute gibt es den Fall
   nicht, weil die Menge wandert.

Topic `t-codex` — "Zuordnen aus dem Codex":
7. `d-weg`, mode `chain`, label "Weg zum Zuordnen", question "Wie ordnest du auf einer Codex-Seite zu?". Routes (each with
   `[data-opt-steps]`): `auswahl` (rec) "Kleine Auswahl": Knopf → Gruppe wählen (new step) → zugeordnet; consequence: Zwei
   Klicks, das Ziel ist immer bewusst gewählt. `direkt` "Ein Klick in die zuletzt genutzte": Knopf → zugeordnet;
   consequence: Am schnellsten, trifft aber still die falsche Gruppe. `hq` "Nur ein Link ins HQ": Knopf → HQ Planen →
   Gruppe wählen → zurück; consequence: Nichts Neues zu bauen, aber die Seite ist weg. Situation: Die Auswahl gibt es im
   Bestand schon (Ziel wählen oder neu anlegen); der Warenkorb führt heute per Link ins HQ. rec-why: Das falsche Ziel
   still zu wählen ist der teuerste Fehler.
8. `d-wieviel`, mode `single`, label "Wie viel", question "Wie viele Stück werden beim Zuordnen vorgeschlagen?". Options:
   `alle` (rec) "Die ganze Wunschmenge, änderbar" — consequence: Ein Klick für den Normalfall, ein Stepper für einen Teil.
   `eins` "Immer 1 Stück" — consequence: Vorsichtig, aber bei 20 Stück 19 Klicks. `fragen` "Immer erst die Zahl eingeben"
   — consequence: Kein Vorschlag, jeder Vorgang ein Schritt länger. Situation: Im HQ wandert heute standardmäßig die ganze
   Menge, teilen ist erlaubt (5 von 20). Stakes: Wie oft du beim Zuordnen nachstellen musst.
9. `d-neu`, mode `yesnoalt`, label "Neue Gruppe aus dem Codex", question "Darf im Codex eine neue Gruppe ohne Einsatz
   entstehen?", rec `yes` (why: Sonst endet der Weg bei 0 Gruppen in einer Sackgasse). yes: Sie entsteht nur mit Namen
   und steht im HQ als „noch ungeplant“. no: Neue Gruppen gibt es nur im HQ; der Codex zeigt dann einen Link dorthin.
   Situation: 7 Plätze; sind alle belegt, ist „neu“ gesperrt.
10. `d-zeilen`, mode `single`, label "Zuordnen in Suchzeilen", question "Kannst du auch aus einer Suchzeile heraus zuordnen?".
   Options: `nur-detail` (rec) "Nein, nur auf der Detailseite" — consequence: Zeilen zeigen nur, dass zugeordnet ist.
   `auch-zeilen` "Ja, über das Zeichen in der Zeile" — consequence: Schneller, aber ein Klick mehr Bedeutung auf 30
   Pixeln. Give it `data-ui-ok` if A13 flags it: it asks which surface may write, not how it looks.
