## Acceptance checklist (every item: done / partial / not done → evidence)

Board `/verse/patches` (embedded in `verse-patches.component.ts`, component `patch-board.component.ts`):
1. **Backup / quick revert:** the current board stays in the code unchanged; the new board is a new component, switched by ONE flag in one place (documented constant + comment "set false to restore the old board"). Revert = flip the flag. Name the file:line in the report.
2. **Live / PTU switch** at the top (segment switch, not scAction). Live is the default. Live hides PTU builds; PTU tab shows only test builds.
3. **Header on Live, two boxes in one row:** left „Gerade auf Live gekommen“ = newest LIVE note of the live line (e.g. 4.10.3) with release date + days, 3–4 headline bullets, „Ganz lesen →“ (anchor into the dossier on that note) and „✓ Gelesen“; right „Als Nächstes auf Live“ = the next line (5.0) with test status, date or „Kein offizielles Datum“ + forecast, roadmap counts.
4. **Roadmap counts quiet:** one line of small chips (bestätigt / möglich / verschoben, only for the statuses the RSI roadmap data actually carries — map honestly, no invented categories), up to 4 item lines below. A chip click opens a **compact** list (round-5 note: not the big popover, size like the rest of the live view), closes on Escape / click beside it (popover rule).
5. **„Alles zu 5.0“ and the 5.0 timeline row** lead to the PTU tab (real anchors / route state, e.g. `?view=ptu`).
6. **Timeline:** cards keep the app's page frame width (no own max-width); rail and dates hang OUT to the left of the frame (date + „seit N Tagen“ / „N Tage live“), the status pill shows only the word (Live / Als Nächstes / Abgelöst). Live line card: newest sub-version (4.10.3) on top, the earlier small patches bundled into one line „N frühere Updates“ that expands.
7. **PTU tab:** the same timeline: every single PTU / Evocati build is its own row with date outside, wave in the pill, newest expanded with its contents, others expand on click; newest test build on top in a header box.
8. **Read state („Lesebestätigung“):** per patch note, stored like `ReleaseSeenService` (`AccountPrefsService` key in `ui_prefs` when signed in, localStorage signed out; no migration). Unread newest note: „Neu für dich“ badge + subtle accent edge, unread dot on rows. After „Gelesen“: content STAYS visible, only badge/glow go, a small „✓ gelesen am …“ and „Nochmal lesen“ / „als ungelesen markieren“. First contact: everything before the newest note counts as read (no wall of dots for history).
9. **Images (round 5 proposal):** header boxes carry a large image of the patch on the right that fades out to the left (mask gradient; text stays readable); each timeline card carries an image at its right edge, fading in; a patch without an image gets a generated stand-in (patch colour, line pattern, version number large and faint, pure CSS/SVG, no AI); 5.0 box shows small roadmap thumbnails. Images come from data the board already loads (roadmap card thumbnails, note images where present) — no new external source.
10. **Patch planet** (`sc-verse-header planet="patches"`): bigger, but its inner (right) edge must not move further into the page; never under text.
11. **Text size:** close to the app's existing board sizes, not larger than today's board.

Dossier (`patch-dossier.component.ts`):
12. **One section order for every dossier** (main line AND point release): Was steckt drin → Stabilität → Community → Dein Urteil → Erste Schritte (only if needed) → Wann kommt der nächste (contains the preparation for the next major patch). Stability no longer first.
13. **Content tiles:** image left, text right; without image: text over the full width; „Behoben“ and „Bekannte Probleme“ as separate lists; a gallery „Bilder aus diesem Patch“ with the note's images; link „Original bei RSI ↗“ stays.
14. **„Vorbereiten“ → „Erste Schritte in diesem Patch“** for the current patch (only when there is something to do, e.g. wipe); the preparation for the next major patch lives under „Wann kommt der nächste“.
15. **Stability vote:** drop the blind mechanic („Erst dein Urteil, dann die Zahl“ / „Zahl ohne Urteil anzeigen“) — the number is shown openly, the question is one line with the answer buttons.

Every new string in `de.json` and `en.json`. Specs for the new pure logic (read state, header selection, timeline/PTU rows, section order).
